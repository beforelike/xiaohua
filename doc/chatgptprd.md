# 《笑画》PRD 补充版：纯语音控制的分层 AI 绘图工具

## 1. 产品定义

《笑话》是一款纯语音控制的 Web 端 AI 绘图工具。用户不使用鼠标和键盘，仅通过语音描述、修改、选择、删除和保存画面内容。

本产品不采用“一句话生成整张图”的方式，而是采用“分层生成 + 对象管理”的方式完成绘图创作。画面中的每个主要元素都作为独立对象存在，例如人物、房子、树、太阳、草地、文字等。每个对象拥有独立图层、位置、大小、旋转、名称、生成提示词和状态，用户可以通过语音对单个对象进行控制。

产品核心目标是让用户像指挥一个 AI 绘画助手一样创作画面：

> “画一片宫崎骏风格的草地。”
>
> “在左边加一棵树。”
>
> “把树变大一点。”
>
> “在右上角加一个太阳。”
>
> “选中刚才的太阳，换成涂鸦风格。”
>
> “删除那棵树。”
>
> “保存作品。”

## 2. 核心设计思路

### 2.1 不是整图生成，而是元素级生成

传统 AI 生图工具通常根据一段 prompt 生成一整张图片，用户很难精确修改其中某一个局部元素。本项目采用元素级生成：

1. 用户通过语音提出绘图需求；
2. 系统将语音转成文字；
3. AI 将自然语言解析为结构化绘图指令；
4. 如果是新增元素，则调用图片生成 API 生成单个透明背景元素；
5. 系统将生成的元素作为独立图层放入画布；
6. 用户可以继续通过语音修改该元素的位置、大小、风格、名称和显示状态。

例如：

用户说：

> “在画面左下角画一只可爱的猫。”

系统生成一个透明背景的猫图像，并创建对象：

```json
{
  "id": "obj_cat_001",
  "name": "可爱的猫",
  "type": "image",
  "layerIndex": 3,
  "prompt": "一只可爱的猫，柔和插画风格，透明背景",
  "position": {
    "x": 160,
    "y": 620
  },
  "size": {
    "width": 240,
    "height": 240
  },
  "rotation": 0,
  "visible": true,
  "locked": false,
  "selected": true
}
```

这样后续用户说“把猫移动到右边”“把猫变小一点”“删除猫”时，系统可以精准操作该对象，而不是重新生成整张图。

## 3. 用户故事

### 3.1 P1 用户故事

#### 用户故事 1：用户可以用语音创建画面元素

作为用户，我希望只通过语音就能往画布中添加元素，例如草地、太阳、树、房子、人物、文字等，而不需要使用鼠标和键盘。

验收标准：

- 用户说出“画一个太阳”，系统能生成太阳对象；
- 生成的对象会出现在画布中；
- 生成对象自动进入当前选中状态；
- 系统给出语音或文字反馈，例如“已添加太阳”。

#### 用户故事 2：用户可以通过语音控制图层

作为用户，我希望每个画面元素都是独立图层，可以被选择、显示、隐藏、删除和调整顺序。

验收标准：

- 系统能展示当前所有图层；
- 当前选中图层有明显标识；
- 用户可以说“选择太阳”“删除太阳”“把太阳放到最上层”；
- 系统能正确操作对应图层。

#### 用户故事 3：用户可以用自然语言完成基础修改

作为用户，我希望不用记固定命令，也可以自然地说“把刚才那个太阳变大一点”“把房子放到右边”。

验收标准：

- 支持“刚才那个”“这个”“它”等上下文代词；
- 支持位置、大小、旋转、图层顺序等基础属性修改；
- 如果系统无法判断对象，需要向用户确认。

#### 用户故事 4：用户可以保存作品

作为用户，我希望在完成创作后，通过语音保存当前作品。

验收标准：

- 用户说“保存作品”后，系统可以导出当前画布图片；
- 同时保存作品的对象数据，方便后续继续编辑；
- 系统反馈保存成功或失败。

#### 用户故事 5：用户能知道系统当前状态

作为用户，我希望知道系统是在听我说话、正在生成、执行成功还是失败。

验收标准：

- 系统至少包含“等待语音”“识别中”“生成中”“执行成功”“执行失败”几种状态；
- 状态可通过界面文字或图标显示；
- 失败时给出原因，例如“没有找到名为太阳的图层”。

## 4. 功能优先级

## P1：两天内必须完成

### 4.1 纯语音输入

用户通过语音发出指令，系统将语音转成文字，并将文字交给指令解析模块处理。

P1 支持的语音指令类型：

- 新增元素：
  “画一个太阳”
  “加一棵树”
  “生成一片草地”
- 选择对象：
  “选择太阳”
  “选中那棵树”
  “选择刚才生成的对象”
- 修改对象：
  “把它放大一点”
  “把太阳移动到右上角”
  “把文字改成红色”
- 删除对象：
  “删除太阳”
  “删除当前选中的对象”
- 保存作品：
  “保存图片”
  “导出作品”

### 4.2 AI 元素生成

用户新增复杂画面元素时，系统调用图片生成 API 生成独立素材。

P1 支持生成：

- 草地
- 太阳
- 树
- 云朵
- 房子
- 简单人物
- 动物
- 装饰图形
- 文字贴纸

生成要求：

- 尽量生成透明背景素材；
- 每个素材独立成为一个图层；
- 每个素材生成后保存 prompt、图片地址、位置、大小等元信息；
- 如果透明背景不可用，则使用抠图或背景去除作为降级方案。

### 4.3 图层系统

画布中的每个元素都作为一个图层存在。

每个图层至少包含以下字段：

```json
{
  "id": "layer_001",
  "name": "太阳",
  "type": "image",
  "visible": true,
  "locked": false,
  "selected": false,
  "zIndex": 1,
  "assetUrl": "",
  "prompt": "",
  "x": 0,
  "y": 0,
  "width": 200,
  "height": 200,
  "rotation": 0
}
```

P1 必须支持：

- 新增图层；
- 删除图层；
- 选择图层；
- 显示当前选中图层；
- 图层上移和下移；
- 保存所有图层数据。

### 4.4 对象管理

用户可以通过语音管理单个画面对象。

P1 支持：

- 选择对象；
- 删除对象；
- 移动对象；
- 缩放对象；
- 重命名对象；
- 查看当前选中对象。

示例：

用户说：

> “把太阳移到右上角。”

系统执行：

```json
{
  "action": "modify",
  "target": "太阳",
  "property": "position",
  "value": "top-right"
}
```

### 4.5 反馈系统

系统需要对用户的每次操作给出反馈。

反馈类型：

- 等待：正在听用户说话；
- 识别：正在识别语音；
- 理解：正在解析指令；
- 生成：正在生成图片元素；
- 成功：操作完成；
- 失败：操作无法执行。

示例反馈：

- “正在生成太阳。”
- “已添加太阳图层。”
- “没有找到名为房子的对象。”
- “当前选中图层是：草地。”
- “生成失败，请换一种描述。”

## P2：加分功能

### 5.1 统一画面风格

为避免不同元素风格混乱，系统设置全局风格提示词。

例如：

```json
{
  "globalStyle": "柔和、童话、手绘插画、温暖色调、统一光照、干净背景"
}
```

当用户生成任何元素时，系统都会自动拼接全局风格：

用户说：

> “画一棵树。”

实际生成 prompt：

> “一棵树，柔和童话手绘插画风格，温暖色调，统一光照，透明背景。”

用户也可以通过语音切换风格：

- “切换成宫崎骏风格”
- “切换成涂鸦风格”
- “让画面更可爱一点”
- “让整体风格更梦幻”

### 5.2 局部重新生成

用户可以选择某个对象后，只重新生成该对象，而不是重做整张画。

示例：

> “选中房子。”
> “把房子改成糖果屋。”

系统只重新生成房子图层，其他图层不变。

### 5.3 预设元素和笔刷

为了减少 API 调用成本和生成等待时间，系统内置常用素材和笔刷。

预设元素包括：

- 宫崎骏风格草地；
- 云朵；
- 星星；
- 小花；
- 树；
- 太阳；
- 月亮；
- 涂鸦文字气泡；
- 箭头；
- 装饰贴纸。

当用户说“画一片草地”时，系统可以优先使用本地预设素材，而不是每次调用 API。

### 5.4 风格文字

支持用户通过语音生成风格化文字。

示例：

> “写上‘今天也要开心’，用活泼的涂鸦文字。”

系统创建一个文字图层，或者生成一张透明背景的文字贴纸图层。

### 5.5 操作历史

支持撤销和重做。

语音指令：

- “撤销”
- “重做”
- “回到上一步”
- “取消刚才的操作”

每次图层变化都记录为一个历史快照。

## P3：高级探索功能

### 6.1 对象拆分

P3 目标是支持对已有图像中的局部进行拆分和替换。

示例：

> “选择人物的手，换成机械手。”

该功能需要图像分割、局部 mask、图像编辑 API 和对象重建能力，开发复杂度较高，因此不放入 P1。

P3 的可能实现流程：

1. 用户选择人物图层；
2. 用户说“选择人物的手”；
3. 系统使用分割模型或手动 mask 生成局部区域；
4. 调用图像编辑 API 将手替换为机械手；
5. 更新人物图层或拆分出新的机械手图层；
6. 保存修改历史。

## 7. 系统架构

整体链路如下：

```text
语音输入
↓
语音识别 ASR
↓
自然语言理解 NLU
↓
结构化指令生成
↓
指令校验与补全
↓
图像生成 / 图层操作 / 对象修改
↓
Canvas 渲染
↓
状态反馈
↓
保存作品
```

### 7.1 模块划分

#### 语音识别模块

负责将用户语音转成文本。

输入：

```text
“在右上角画一个太阳”
```

输出：

```text
在右上角画一个太阳
```

#### 指令解析模块

负责将自然语言转成结构化命令。

输出示例：

```json
{
  "action": "create",
  "objectType": "image",
  "name": "太阳",
  "prompt": "一个可爱的太阳，柔和手绘插画风格，透明背景",
  "position": "top-right",
  "size": "medium"
}
```

#### 图像生成模块

负责调用图片生成 API，生成单个画面元素素材。

输入：

```json
{
  "prompt": "一个可爱的太阳，柔和手绘插画风格，透明背景",
  "size": "512x512",
  "background": "transparent"
}
```

输出：

```json
{
  "assetUrl": "https://xxx/sun.png",
  "width": 512,
  "height": 512
}
```

#### 画布渲染模块

负责将生成的图片元素放到画布中，并维护位置、大小、旋转、图层顺序等属性。

#### 图层管理模块

负责管理所有对象的层级、可见性、选中状态、命名和删除。

#### 状态反馈模块

负责告诉用户系统当前状态，例如正在生成、已完成、失败等。

## 9. 指令能力设计

### 9.1 创建类指令

用户可以说：

- “画一个太阳”
- “加一棵树”
- “生成一片草地”
- “在中间画一个小房子”
- “写上‘欢迎来到我的世界’”

系统行为：

1. 判断是否需要调用图片生成 API；
2. 生成透明背景元素；
3. 创建图层；
4. 放置到指定位置；
5. 选中新图层；
6. 反馈用户。

### 9.2 选择类指令

用户可以说：

- “选择太阳”
- “选中树”
- “选择刚才那个”
- “选中最上面的图层”

系统行为：

1. 在图层列表中查找对象；
2. 如果找到唯一对象，则选中；
3. 如果找到多个对象，则询问用户；
4. 如果没找到，则反馈失败。

### 9.3 修改类指令

用户可以说：

- “把太阳放大一点”
- “把树移动到左边”
- “把房子旋转一点”
- “把文字改成红色”
- “把草地换成更梦幻的风格”

系统行为：

1. 找到目标图层；
2. 判断是属性修改还是重新生成；
3. 如果是位置、大小、旋转，直接修改对象属性；
4. 如果是风格、内容、外观变化，则重新生成该图层素材；
5. 更新画布和历史记录。

### 9.4 删除类指令

用户可以说：

- “删除太阳”
- “删除当前对象”
- “把树删掉”

系统行为：

1. 找到目标图层；
2. 删除图层；
3. 更新图层列表；
4. 记录历史；
5. 反馈删除成功。

### 9.5 保存类指令

用户可以说：

- “保存作品”
- “导出图片”
- “保存当前画面”

系统行为：

1. 导出合成图片；
2. 保存图层 JSON；
3. 反馈保存成功。

## 10. 容错策略

### 10.1 低置信度确认

当指令解析置信度较低时，系统不直接执行，而是询问用户：

> “我理解你想生成一个蓝色房子，是否确认？”

### 10.2 多对象歧义处理

如果画面中有多个相似对象，例如多个太阳或多棵树，系统需要让用户确认：

> “画面中有 3 棵树，你想操作左边、中间还是右边的树？”

### 10.3 API 生成失败降级

如果图片生成失败，系统可以：

1. 重试一次；
2. 使用本地预设素材；
3. 使用简单矢量图形代替；
4. 告知用户失败原因。

### 10.4 透明背景失败降级

如果生成图片无法获得透明背景，则：

1. 尝试背景去除；
2. 或生成白底贴纸；
3. 或提示用户“当前素材背景未完全透明”。

## 11. 成本控制策略

### 11.1 只生成对象，不生成整图

系统只在新增或重新生成单个对象时调用图片生成 API，避免每次修改都重新生成整张图。

例如：

- “把太阳移动到右上角”：不调用 API，只修改位置；
- “把太阳变大一点”：不调用 API，只修改尺寸；
- “把太阳换成月亮”：调用 API，只重新生成该图层。

### 11.2 本地预设素材优先

对于高频元素，优先使用本地素材：

- 草地；
- 云朵；
- 太阳；
- 星星；
- 树；
- 花；
- 箭头；
- 文字气泡。

这样可以减少 API 调用次数，也能降低响应延迟。

### 11.3 Prompt 缓存

如果用户多次生成相似对象，系统可以复用已生成素材。

缓存 key 可以由以下信息组成：

```text
对象名称 + 风格 + 颜色 + 视角 + 尺寸
```

例如：

```text
太阳_童话插画_黄色_正面_512
```

### 11.4 分辨率分级

P1 默认使用较低分辨率生成元素，例如 512x512。只有在用户导出高清图时，才按需重新生成高分辨率素材。

### 11.5 操作前确认

对于高成本操作，例如“重新生成整张画面”“把所有对象都换成赛博朋克风格”，系统需要先确认：

> “这个操作需要重新生成多个图层，可能耗时较长，是否继续？”

5. 用户说：“在左边加一棵大树。”
6. 系统生成树图层。
7. 用户说：“在右上角加一个太阳。”
8. 系统生成太阳图层。
9. 用户说：“把太阳变小一点。”
10. 系统直接修改太阳尺寸，不重新生成。
11. 用户说：“选中树，把它换成更梦幻的风格。”
12. 系统只重新生成树图层。
13. 用户说：“显示当前图层。”
14. 系统展示图层列表并标记当前选中图层。
15. 用户说：“保存作品。”
16. 系统导出图片并保存图层数据。

## 14. 未完成部分说明

由于项目周期只有两天，以下能力暂不作为 P1 完成：

1. 人物局部拆分，例如选择人物的手；
2. 多对象复杂组合编辑；
3. 高清多图层批量重新生成；
4. 精确语义分割；
5. 复杂遮挡关系处理；
6. 多端同步和云端作品库。

这些功能需要图像分割、mask 编辑、图像编辑 API、对象识别和更复杂的画布状态管理，适合作为后续版本继续开发。

## 15. 项目亮点

1. 不是简单的语音版 AI 生图，而是语音控制的分层 AI 绘图工具；
2. 每个 AI 生成元素都是独立图层，可被选择、删除、移动和重新生成；
3. 支持上下文指令，例如“刚才那个”“它”“当前选中的对象”；
4. 支持局部修改，只重新生成单个对象，降低成本；
5. 通过全局风格 prompt 保证画面风格统一；
6. 支持保存最终图片和图层数据，具备继续编辑的基础。
