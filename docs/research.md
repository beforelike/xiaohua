# 技术调研与决策

## ADR-01 画布渲染

**决策：** 使用 Konva / react-konva。

**原因：** 提供成熟的图层、图片节点、变换器和画布导出能力，适合对象级编辑。原生 Canvas 开发量过大，DOM 叠放在导出和复杂变换上成本更高。

## ADR-02 状态管理

**决策：** 使用 Zustand 管理项目、选择状态和命令执行状态。

**原因：** API 简洁，适合两天 P1；领域命令可在独立 store/action 中测试。避免为小型单页应用引入更重的状态框架。

## ADR-03 语音识别

**决策：** P1 优先 Web Speech API，通过 `SpeechRecognitionAdapter` 隔离。

**原因：** 浏览器端接入快且适合演示。其兼容性和网络依赖不稳定，因此必须检测能力并允许替换为云端 ASR；开发环境提供文本 Mock。

## ADR-04 指令理解

**决策：** 服务端调用大模型输出受约束 JSON，客户端再做确定性校验和目标解析。

**原因：** 自然语言变化多，纯正则难覆盖；但不能信任模型直接执行。常见命令可先由本地快速规则识别，降低延迟和成本。

## ADR-05 图片生成

**决策：** 定义 `ImageGenerationProvider`，供应商由环境变量配置。

**原因：** PRD 只要求至少接入一个生成 API，尚未确定预算和账号。适配器统一透明背景、尺寸、超时和错误语义；开发与测试使用预设素材或 Mock。

## ADR-06 服务端边界

**决策：** 浏览器只访问本项目 API，模型密钥仅在服务端。

**原因：** 防止密钥泄漏，集中实施限流、Schema 校验、日志脱敏、缓存和供应商切换。

## ADR-07 保存策略

**决策：** P1 使用浏览器下载 PNG 与 JSON，不引入数据库。

**原因：** 满足保存和继续编辑基础需求，显著降低两天开发风险。后续云端作品库再引入持久化与账号系统。

## ADR-08 历史与命令

**决策：** 所有画布变更通过命令执行器，P1 先保存最近命令和必要快照。

**原因：** 统一错误处理并为 P2 撤销重做打基础，不在 P1 暴露未完成的历史 UI。

## 风险表

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 语音 API 不兼容 | 无法演示纯语音 | Chrome/Edge 基线、能力检测、文本 Mock |
| 透明背景生成失败 | 图层出现方形底色 | 背景去除、预设素材、贴纸式降级 |
| 模型输出非法 JSON | 错误操作画布 | Schema 校验、动作白名单、拒绝执行 |
| 重名对象歧义 | 操作错误对象 | 位置描述、最近对象、用户确认 |
| API 延迟或配额不足 | 演示中断 | 超时、一次重试、缓存、预设素材 |
| 浏览器导出跨域污染 | PNG 导出失败 | 服务端代理素材、同源缓存、CORS 校验 |
