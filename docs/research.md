# 技术调研与决策

## ADR-01 画布渲染

**决策：** 使用 Konva / react-konva。

**原因：** 提供成熟的图层、图片节点、变换器和画布导出能力，适合对象级编辑。原生 Canvas 开发量过大，DOM 叠放在导出和复杂变换上成本更高。

## ADR-02 状态管理

**决策：** 使用 Zustand 管理项目、选择状态和命令执行状态。

**原因：** API 简洁，适合两天 P1；领域命令可在独立 store/action 中测试。避免为小型单页应用引入更重的状态框架。

## ADR-03 语音识别

**决策：** P1 使用本地 ASR 服务，通过 `SpeechRecognitionAdapter` 隔离；Web Speech API 仅作为可选降级。

**原因：** Chrome 的 Web Speech API 可能依赖境外网络，无法保证中国大陆可用。本地 Whisper、faster-whisper 或同类 ASR 可以离线运行；开发环境仍提供文本 Mock。

## ADR-04 指令理解

**决策：** 常用 P1 命令优先由本地确定性规则解析；复杂表达可选用本地大语言模型输出受约束 JSON，客户端再做校验和目标解析。

**原因：** 本地规则能覆盖演示命令并保证中国大陆离线可用。自然语言变化较多时可接入本地模型，但不能信任模型直接执行。

## ADR-05 图片生成

**决策：** 使用本地 Stable Diffusion WebUI REST API，实现 `ImageGenerationProvider`。兼容 AUTOMATIC1111 和提供相同 API 的 Forge。

**原因：** 本地 API 不依赖境外网络，没有按次调用成本，适合中国大陆本地演示。适配器统一调用 `/sdapi/v1/txt2img`、尺寸、超时和错误语义；开发与测试使用预设素材或 Mock。透明背景通过纯色背景生成后本地抠图，或使用支持透明输出的扩展。

## ADR-06 服务端边界

**决策：** 浏览器只访问本项目本地 API；Stable Diffusion WebUI 和 ASR 地址由服务端环境变量配置。

**原因：** 避免浏览器跨域问题，并集中实施 Schema 校验、超时、缓存和服务切换。本地服务默认只监听回环地址，不直接暴露公网。

## ADR-07 保存策略

**决策：** P1 使用浏览器下载 PNG 与 JSON，不引入数据库。

**原因：** 满足保存和继续编辑基础需求，显著降低两天开发风险。后续云端作品库再引入持久化与账号系统。

## ADR-08 历史与命令

**决策：** 所有画布变更通过命令执行器，P1 先保存最近命令和必要快照。

**原因：** 统一错误处理并为 P2 撤销重做打基础，不在 P1 暴露未完成的历史 UI。

## 风险表

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 本地 ASR 未启动或模型缺失 | 无法演示纯语音 | 健康检查、启动指引、文本 Mock |
| 透明背景生成失败 | 图层出现方形底色 | 背景去除、预设素材、贴纸式降级 |
| 模型输出非法 JSON | 错误操作画布 | Schema 校验、动作白名单、拒绝执行 |
| 重名对象歧义 | 操作错误对象 | 位置描述、最近对象、用户确认 |
| 本地显存不足或生成过慢 | 演示中断 | 512 分辨率、低步数、缓存、预设素材 |
| 浏览器导出跨域污染 | PNG 导出失败 | 服务端代理素材、同源缓存、CORS 校验 |
