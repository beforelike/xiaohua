# 笑画项目准则

版本：1.0.0  
批准日期：2026-06-12

## 一、语音优先

P1 的完整创作主流程必须能仅靠语音完成。鼠标和键盘可以用于开发调试及无障碍降级，但不能成为创建、选择、修改、删除和保存的必需条件。

## 二、对象即图层

主要画面元素必须拥有稳定 ID 和独立图层数据。位置、尺寸、旋转、可见性、层级、生成提示词和素材来源必须可单独保存与修改。禁止以整图重新生成替代普通对象操作。

## 三、结构化命令先于执行

自然语言不能直接修改画布。所有指令必须先转换为受版本控制的结构化命令，再经过 Schema、动作白名单、目标存在性和置信度校验。低置信度或多目标歧义必须确认。

## 四、可恢复与可降级

外部语音或模型 API 失败不能破坏当前作品。生成失败按“有限重试、缓存、预设素材、简单图形、明确提示”降级。所有变更以原子命令执行，为撤销重做保留扩展空间。

## 五、安全与隐私

密钥只存在于服务端。日志不得记录密钥、完整音频或不必要的个人信息。上传内容必须限制类型和大小；模型输出、URL 和文件名必须校验。

## 六、两天 P1 优先

先完成可演示闭环，再增加效果。P1 不包含人物局部分割、复杂遮挡编辑、云端作品库、多端同步和高清批量重绘。新增范围必须说明对时间和稳定性的影响。

## 七、持续且可审查的交付

功能通过小分支、小提交和单一职责 PR 交付。PR 必须描述功能、实现、测试和复用来源。主分支始终保持可运行；不得通过改写时间戳伪造持续开发记录。

## 八、质量标准

- TypeScript 启用严格模式，禁止无说明的 `any`。
- 领域逻辑与 UI 解耦，外部服务使用适配器。
- 核心命令解析、目标解析、状态变更和导出必须有自动化测试。
- 用户可见错误使用中文并给出恢复建议。
- UI 使用中文，状态不能只靠颜色表达。

## 治理

本准则优先于局部实现偏好。变更需通过 PR，说明原因、影响和迁移方案；版本遵循语义化版本。每个功能 PR 在合并前检查准则合规性。
